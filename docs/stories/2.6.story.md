## Descricao

Implementar a pagina de configuracoes do painel administrativo. O foco principal e o editor de descontos por tier (Bronze, Silver, Gold), que atualmente usa valores hardcoded. Alem disso, permitir configuracoes gerais do app armazenadas na tabela `app_config`.

### Schema de Configuracao (referencia `database.ts`)
```typescript
interface AppConfig {
  id: string
  key: string
  value: Record<string, unknown>  // JSON flexivel
  created_at: string
}

interface TierDiscounts {
  silver: number   // percentual de desconto (ex: 4 = 4%)
  gold: number     // percentual de desconto (ex: 8 = 8%)
}
```

### Funcionalidades
1. **Editor de Descontos por Tier** - Formulario para ajustar percentuais de desconto Bronze (sempre 0%), Silver (default 4%), Gold (default 8%)
2. **Configuracoes Gerais** - Secao expansivel para futuras configs (nome do app, contato, etc.)
3. **Persistencia** - Salvar na tabela `app_config` do Supabase
4. **Feedback Visual** - Preview do impacto das mudancas antes de salvar

## Notas Tecnicas

- **Upsert AppConfig**: Usar `supabase.from('app_config').upsert({ key, value }, { onConflict: 'key' })`. Verificar se a tabela tem constraint UNIQUE em `key`.
- **Config Store**: Verificar se o `config-store.ts` ja le de `app_config` ou se usa valores hardcoded. Se hardcoded, refatorar para buscar do Supabase.
- **Preview de Desconto**: Para o calculo de preview, usar preco base de R$ 100,00 e aplicar: `preco * (1 - desconto/100)`. Exibir formatado em BRL.
- **Dirty State**: Manter estado `isDirty` comparando valores atuais com valores salvos.
- **Bronze**: O tier Bronze sempre tem 0% de desconto. Nao e editavel. Exibir como referencia.
- **Impacto**: Ao salvar novos descontos, todos os precos exibidos no catalogo do lado cliente mudarao na proxima carga. Nao e necessario recalcular pedidos existentes.
