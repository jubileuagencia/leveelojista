## Story

**As a** gestor da agência,
**I want** que todas as ações de workflow sejam automaticamente registradas no activity log,

## Descricao

O `activity-logger.ts` já existe com os tipos `workflow.started`, `workflow.step_completed` e `workflow.completed`, mas **nunca é chamado** no código de workflows. Além disso, outras mutations do sistema (tasks, clients, deliverables) também não logam atividade.

Esta story:
1. Integra o activity logger nos workflows (chamadas explícitas)
2. Cria um utility wrapper para facilitar logging em qualquer módulo
3. Conecta o feed de atividades do dashboard com dados reais

### Funcionalidades

1. **Workflow logging** — Chamar logActivity em: start, step complete, step skip, step fail, workflow complete
2. **Log utility** — Helper `logWorkflowActivity()` que abstrai os parâmetros comuns
3. **Dashboard activity feed** — Widget de atividades mostra eventos reais do banco
4. **Activity page** — `/activity` lista atividades com filtro por módulo e período

- [ ] CA4: Ao falhar step, log `workflow.step_failed` (novo tipo) com failure_reason
- [ ] CA5: Dashboard widget "Atividade Recente" mostra eventos reais (últimas 10 atividades)

- [ ] CA7: Atividades incluem metadata útil (workflow name, step title, duração)

## Notas Tecnicas

- **Fire-and-forget**: Logging NUNCA deve bloquear a operação principal. Usar `void logActivity()` sem await
- **Dev mode**: Em dev mode, logar no console em vez do banco (já implementado no logger)
- **Rate limiting**: Não precisa por agora (ações manuais são infrequentes)
- **Metadata structure**: Incluir sempre `{ workflowName, executionId }` como base
