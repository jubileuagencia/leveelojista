## Descricao

Implementar o modulo de gestao de pedidos no painel administrativo. O admin precisa ver todos os pedidos de todos os clientes, buscar por numero do pedido, empresa ou CNPJ, filtrar por status (multi-select), ver detalhes completos de cada pedido e alterar status individualmente ou em massa.

### Schema do Pedido (referencia `database.ts`)
```typescript
interface Order {
  id: string
  order_number: number       // Numero amigavel (#1001, #1002...)
  user_id: string
  address_id: string | null
  status: OrderStatus        // 'pending' | 'approved' | 'preparing' | 'shipped' | 'delivered' | 'rejected' | 'cancelled'
  payment_method: PaymentMethod  // 'pix' | 'boleto'
  subtotal: number
  discount: number
  total: number
  created_at: string
  profile?: Profile          // Join com perfil do cliente
  address?: UserAddress      // Join com endereco de entrega
  items?: OrderItem[]        // Join com itens do pedido
}
```

### Fluxo de Status
```
pending -> approved -> preparing -> shipped -> delivered
pending -> rejected
pending -> cancelled (pelo cliente)
approved -> cancelled (pelo admin)
```

### Funcionalidades
1. **Listagem** - Tabela paginada com todos os pedidos (mais recentes primeiro)
2. **Smart Search** - Busca por `order_number`, `company_name` ou `cnpj`
3. **Filtro por Status** - Multi-select com todos os 7 status
4. **Modal de Detalhes** - Informacoes completas do pedido
5. **Mudanca de Status** - Individual (dropdown/select no modal ou na tabela)
6. **Bulk Status Change** - Selecionar multiplos pedidos e alterar status em massa

## Notas Tecnicas

- **Join Complexo**: Para listagem, fazer join com `profiles` para exibir empresa e CNPJ: `.select('*, profile:profiles(company_name, cnpj)')`. Para detalhes, join completo com address e items.
- **Busca Smart**: Detectar se input e numerico (`/^\d+$/`) para buscar por `order_number`, caso contrario buscar por `company_name` ou `cnpj` no profile (requer join ou RPC).
- **Busca por Profile**: Supabase nao permite `.ilike()` em campos de foreign table no `.select()`. Opcoes: (a) criar RPC `search_admin_orders(term)`, (b) buscar profiles primeiro e depois filtrar por `user_id`. Recomendacao: criar RPC para performance.
- **Transicoes de Status**: Implementar mapa de transicoes validas no frontend:
  ```typescript
  const VALID_TRANSITIONS: Record<OrderStatus, OrderStatus[]> = {
    pending: ['approved', 'rejected', 'cancelled'],
    approved: ['preparing', 'cancelled'],
    preparing: ['shipped'],
    shipped: ['delivered'],
    delivered: [],
    rejected: [],
    cancelled: [],
  }
  ```
- **Bulk Actions**: Ao alterar status em massa, validar que todos os pedidos selecionados aceitam a transicao. Exibir warning se algum nao aceitar.
- **Formatacao**: Order number exibir como `#1001`. Datas em formato `dd/mm/yyyy HH:mm`. Valores em BRL.
- **Performance**: Para listagem, nao carregar items do pedido. So carregar items no modal de detalhes.
