## Descricao

Implementar a pagina principal do painel administrativo (Dashboard) com cards de metricas-chave do negocio, tabela de pedidos recentes e, opcionalmente, um grafico de distribuicao de pedidos por status.

O dashboard deve consultar dados reais do Supabase e exibir informacoes atualizadas. E a primeira tela que o admin ve ao acessar `/admin`.

### Metricas nos Cards
1. **Total de Pedidos** - contagem total de pedidos na base
2. **Pedidos Hoje** - pedidos criados na data atual
3. **Total de Clientes** - contagem de perfis cadastrados
4. **Receita Mensal** - soma do campo `total` dos pedidos do mes corrente com status != `cancelled` e != `rejected`

### Pedidos Recentes
- Tabela com os ultimos 5 pedidos ordenados por `created_at DESC`
- Colunas: # Pedido, Empresa, Status, Total, Data
- Link para detalhes (futuro - Story 2.3)

### Grafico por Status (Opcional)
- Distribuicao de pedidos agrupados por `OrderStatus`
- Pode ser bar chart ou donut chart simples
- Usar cores semanticas para cada status

## Notas Tecnicas

- **Queries Supabase**: Usar `.select('*', { count: 'exact' })` para contagens eficientes. Para receita mensal, filtrar por `created_at` >= primeiro dia do mes e status not in ('cancelled', 'rejected'), depois somar `total`.
- **Join Profile**: Na tabela de pedidos recentes, fazer join com `profiles` para exibir nome da empresa: `.select('*, profile:profiles(company_name)')`.
- **Timezone**: Pedidos "de hoje" devem considerar timezone America/Sao_Paulo. Usar `new Date()` com ajuste ou filtrar no Supabase com `gte` no timestamp.
- **Formatacao**: Usar `Intl.NumberFormat('pt-BR', { style: 'currency', currency: 'BRL' })` para valores monetarios.
- **Cores de status**: Manter consistencia com as cores ja usadas no lado cliente (OrdersPage).
- **Performance**: Dashboard pode ser heavy. Considerar cache ou stale-while-revalidate se usar React Query.
