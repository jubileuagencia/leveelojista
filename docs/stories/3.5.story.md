## Descricao

Atualmente todos os steps são executados linearmente (step 1, depois 2, depois 3...). A Story 3.1 adicionou o campo `dependsOn` no schema, mas sem lógica de enforcement.

Esta story implementa a engine de dependências que:
1. Calcula quais steps estão disponíveis baseado no grafo de dependências
2. Permite execução paralela de steps independentes
3. Bloqueia steps cujas dependências não foram concluídas
4. Mostra visualmente o estado de cada step (bloqueado, disponível, ativo, concluído)

### Exemplos de Uso

**Workflow linear** (comportamento atual):
```
Step 1 → Step 2 → Step 3
```

**Workflow com paralelismo**:
```
Step 1 (Briefing)
  ├→ Step 2a (Copy) [dependsOn: step-1]
  ├→ Step 2b (Design) [dependsOn: step-1]
  └→ Step 3 (Revisão) [dependsOn: step-2a, step-2b]
```

**Workflow com branch**:
```
Step 1 (Análise)
  ├→ Step 2 (API Integration) [dependsOn: step-1]
  └→ Step 3 (Frontend) [dependsOn: step-1]
Step 4 (QA) [dependsOn: step-2, step-3]
```

### Funcionalidades

1. **Dependency resolver** — Função que calcula steps disponíveis dado o estado atual
2. **Parallel execution** — Múltiplos steps disponíveis ao mesmo tempo
3. **Visual graph** — Steps bloqueados ficam com opacidade reduzida + ícone de cadeado
4. **Auto-advance inteligente** — Ao completar step, ativar todos os steps que ficaram desbloqueados
5. **Cycle detection** — Validar que não há dependências circulares ao criar/editar workflow
6. **Backward compat** — Workflows sem dependsOn continuam funcionando linearmente

## Criterios de Aceite

- [ ] CA1: Steps com `dependsOn` só ficam disponíveis quando todas as dependências estão `completed` ou `skipped`
- [ ] CA2: Steps sem `dependsOn` e sem dependentes ficam disponíveis desde o início
- [ ] CA3: Múltiplos steps podem estar `in_progress` simultaneamente quando são paralelos
- [ ] CA4: Steps bloqueados mostram ícone de cadeado e lista de dependências pendentes
- [ ] CA5: Ao completar step, todos os steps desbloqueados automaticamente mudam para `available`
- [ ] CA6: Validação no WorkflowBuilder impede dependências circulares
- [ ] CA7: Workflows existentes (sem dependsOn) continuam funcionando com auto-advance linear
- [ ] CA8: Ao iniciar workflow, todos os steps sem dependsOn ficam disponíveis (não apenas o primeiro)

## Notas Tecnicas

- **Cycle detection**: Usar DFS com visited set — O(V+E), eficiente para grafos pequenos
- **Backward compat**: Se nenhum step tem `dependsOn`, manter auto-advance linear (step N → step N+1)
- **Skip propagation**: Se um step é skipped, seus dependentes ficam disponíveis (skip conta como "concluído")
- **Failed propagation**: Se um step falha, dependentes ficam bloqueados até retry+complete ou skip
- **Max parallel**: Sem limite artificial — todos os steps desbloqueados ficam disponíveis
